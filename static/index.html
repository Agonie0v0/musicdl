设置

所有设置保存在服务端 config.json，保存后立即重建音源客户端生效。

音源选择

Cookie 设置（按音源）

从浏览器开发者工具（F12 → 网络 → 请求头 Cookie）整串复制粘贴即可，无需手动拆分。 例：网易云粘贴含 MUSIC_U=… 的整串 Cookie 可解锁 VIP 音质；QQ 音乐粘贴含 qm_keyst=… 的 Cookie。留空则匿名访问。

基础设置

下载分类方式

决定歌曲下到 下载目录 里怎么归类。想直接喂给 navidrome / Jellyfin 建议选“歌手 / 专辑”。

歌词保存方式

决定下载时歌词怎么存。播放器多数认单独的 .lrc 文件；部分媒体库 / 车机认歌曲内嵌歌词。

代理作用范围

上面填了 HTTP 代理才生效。国内音源通常不需要代理，只有 Spotify / YouTube / 苹果等国际音源要走代理时，选“仅指定音源”并勾选它们即可。

高级开关 默认全关即可，搜不到 / 播放失败时再逐个试

专家选项：按音源写 JSON 覆盖（一般用不到，可跳过）

给单个音源单独调参用，键是完整音源名（如 "NeteaseMusicClient"）。留 {} 表示不覆盖。 用法举例见 README「设置项详解」。改错会导致该音源初始化失败，拿不准就别动。

关于 musicdl 引擎

搜索 / 播放 / 下载由 musicdl 引擎完成，各音源能否用取决于它。它是可独立升级的： 升级只会带来各音源的修复，不需要改本项目（本站对它的增强做了兼容保护，拿不到就自动跳过）。

musicdl 版本：…

「一键升级并重启」会自动完成 pip install -U musicdl → 重启服务 → 刷新页面，全程约半分钟。 （本地请用 start 脚本启动才能自动拉起；Docker 由 restart 策略自动拉起，但重建镜像后需再升一次或改用 docker compose up -d --build。）

保存后立即生效，无需重启
